# 架构总览

> 本文只讲**结构**：谁在什么位置、数据往哪流、哪条边界不许越。每个模块的契约写在
> **该文件头部的 docstring** 里（那是权威源），本文不复述。
> 本文底稿来自上游的同一份文档，**界面层与「本仓库独有」两处已按本仓库改写**（见
> [索引.md](索引.md) 的「与上游的差异」）。

---

## 一、分层

```
入口层   run_gui.py / run_gui.bat / `python -m vlt.gui` / vlt/app.py（CLI）/ vlt/selfcheck.py（产物自检）
  │
界面层   vlt/gui.py（薄壳；`_DELEGATE_MAP` 就在它里面）+ gui_*.py（按功能域拆出的实现）
         + ui_*.py（纯文本 / 主题 / Tk 底层）
  │                    ▲ 界面**持有**手腕屏与桌面字幕实例（创建走 gui_engine.start_overlay/start_desktop）
引擎层   vlt/engine.py（Engine / _pump_capture / _send_gated / to_16k_mono）
  │
会话层   vlt/session/base.py（抽象 + 代次分派） → vlt/session/qwen38.py（3.8 / 3.5 事件分派）
  │
输出层   vlt/output/merger · chatbox · overlay（共享渲染）· openvr_overlay(Windows)
         · openxr_overlay(Linux) · desktop_overlay · virtualmic · micproxy · level_match
  │
房间层   vlt/room/*（客户端）+ server/（Cloudflare Worker + Durable Object，独立部署）
  │
平台层   vlt/platform/__init__.py（**门面**）· base(协议) · audio · win · linux · wayland · x11
         · overlay_pixels
  │
支撑层   config · config_io · credentials · endpoints · devices · paths · crashlog
         · version · update_check · textin · tts · voices · i18n · locales · glossary_text
  │
本仓库增强  sfx（通联开关音）· voice_lab + gui_voicelab（音色设计与复刻）· latency（延迟埋点）
```

依赖方向**单向向下**：界面层不写平台分支，引擎层不 import tkinter，会话层不认识界面。
共享代码碰平台能力**只允许**走 [vlt/platform/\_\_init\_\_.py](../../vlt/platform/__init__.py) 门面
（门面里缺实现时返回**安全默认值**，而不是崩）—— 这是 Linux / Windows 能共用一份代码的前提。

## 二、装配：谁构造谁

- **GUI 路径**：[vlt/gui.py](../../vlt/gui.py) 建界面 → [vlt/gui_engine.py](../../vlt/gui_engine.py) 的
  `start_engine()` 造 [Engine](../../vlt/engine.py)，并把**界面持有的**手腕屏 / 桌面字幕实例从 sinks 里剔掉：
  `own_sinks = {s for s in ctx.sinks if s not in ("overlay", "desktop")}`。
  理由写在原地注释里 —— 一块屏要显示两个方向的对话，交给两个引擎各建一次会撞
  `OverlayError_KeyInUse`。
- **CLI 路径**：[vlt/app.py](../../vlt/app.py) 自己组装「会话 + 节流器 + chatbox」；这条路上
  引擎的 `_overlay` 才可能非空。**改「每帧要对实例做点什么」的逻辑时必须两条 tick 都接**
  （引擎 `_pump_loop` 与 `gui_chat.poll` 的 tick 段）—— 只接手边那一条是这类改动的高发缺口。
- **麦克风代理**：界面构造即起代理（`gui_engine` / `gui.py` 的 `_start_proxy`），把
  `proxy.translated_sink` 作为 `audio_sink=` 注入引擎；引擎**不自建也不 close** 它
  （`_owns_virtualmic=False`，见 [vlt/engine.py](../../vlt/engine.py) 的 `_setup_virtualmic` 与 `_cleanup`）。
  代理不在 → 引擎回到「自建虚拟声卡、随翻译启停」的旧行为。
- **打包自检**：[vlt/selfcheck.py](../../vlt/selfcheck.py) 是无头入口，`--self-test` 的判据是
  退出码 0 + stdout 有 `GUI_SELFTEST_OK` + **本次**那份日志里也有。

## 三、两条音频链路（端到端）

```
麦克风路（"我说的话"）            环回路（"别人说的话"）
  win.open_mic / linux pw-record     VRChat 播放端点（WASAPI loopback / PipeWire monitor）
        │ 按设备原生采样率 + 原生声道                  │ 同样原生规格
        ▼                                             ▼
  _pump_capture(gate=None)                    _pump_capture(gate=input_gate)
        │                                             │
        └────────────► to_16k_mono(chunk, rate, channels) ◄────────────┘
                                     │  唯一的重采样入口
                                     ▼
                              _send_gated(...)  → session.send_audio()
                                     │
                                     ▼
                     _SessionProxy → _SilenceGate（长静音闸门）
                                     │
                                     ▼
                              服务端实时会话（WebSocket）
```

| | 麦克风路 | 环回路 |
|---|---|---|
| 采集入口 | `platform.capture_backend().open_mic`（Windows）/ `pw-record`（Linux） | loopback 采集（Windows `pyaudiowpatch` / Linux 按 VRChat 输出流） |
| 打开规格 | **按设备原生采样率与原生声道数**（入参 16k 只是「拿不到原生时的兜底」） | 同左（WASAPI 共享模式只接受端点自己的采样率；声道压成 2 会被直接拒） |
| 电平门限 `_LevelGate` | **不接**（`gate=None`） | **接**（`capture.gate_*`，默认 -35 dBFS）——「远处小声的玩家该被滤掉」 |
| 重采样 | 交给共用泵的 `to_16k_mono` | 同一处，口径唯一 |
| 静音上送 | **永不因「用户不说话」而停**：每块都发（唯一会暂停的是 `_SilenceGate` 的长静音闸门，默认 30s） | 受门限影响：低于门限整段不发 → 服务端收不到停顿就不会收尾 |

⚠️ 由此推出两条**判据口径**（踩过）：

- 「距上次 `send_audio` 的间隔」在真实麦克风链路上恒 ≈0.1s，**不能**当「用户说完了」的信号；
  要判「在说 / 不说了」用**电平**（`_SessionProxy.send_audio` 里算的 `loud = peak >= SILENCE_PEAK`）。
- 归因这类问题**必须按路分开**：麦克风路与环回路是两个病，别并成一句话。

## 四、文本扇出与输出腿的归属

引擎收到会话的 `TextDelta` 后（[vlt/engine.py](../../vlt/engine.py) 的 `_on_text`）：

1. 先过**本地 repeat 抑制**（连续 N 条终版高度雷同 → 全输出面都不刷 + 主动重建会话）；
2. `events.on_text(src, txt, final)` → GUI 侧队列 → 聊天气泡 / 手腕屏 / 桌面字幕 / 房间上行；
3. 引擎自持的 `_overlay.update()`（仅 CLI 路径非空）；
4. `chatbox_payload()` → `Merger` → `Chatbox`（OSC `/chatbox/input`）。

| 输出腿 | 谁持有生命周期 | 约束 |
|---|---|---|
| 聊天气泡（界面） | 界面 | 两个方向都刷 |
| chatbox 气泡 | **引擎** | **只对「我说的话」方向有意义**（`_chatbox_wanted`），对方译文不进气泡 |
| 手腕屏 | **界面**（`gui_engine.start_overlay` / `gui_desktop`） | 一块屏显示两个方向；由界面建/销毁 |
| 桌面字幕 | **界面**（`gui_engine.start_desktop` / `push_desktop`） | 与手腕屏**配置彻底解耦**（自带一整套视觉键，不从 `overlay:` 继承） |
| 译音（虚拟声卡） | 代理在跑 → 代理；否则引擎 | 注入与自建互斥，同一端点**只有一个 owner**；**出口只有一个** `_emit_translated`（见 §七） |
| 句首/句尾「哔」 | 引擎（`vlt/sfx.py`） | 本仓库独有；音量由 `sfx_gain` 独立管，**不**走译音音量匹配 |
| 房间中继 | 界面（`SourcePublisher`） | **只上行「我自己说的话」的源文**；靠 `source_id` 排除 loopback 那条腿（防二次广播 / 回环） |

房间链路的边界：客户端广播的是**每个人的 ASR 源文**，服务端**只转文字**（不翻译、不合成、
不缓冲、不排序、不落库，见 [server/README.md](../../server/README.md)）。房间帧另带一个
`tr` 字段（只在 final 帧）用于同语言比对 —— **不要**把它写进 `RoomMessage.translated`。

## 五、界面层：薄壳 + 委派表 + 可打桩性

`vlt/gui.py` 是**薄壳**：大部分方法只有一行「转发到 `gui_*.py` 的实现」，另有一张
`_DELEGATE_MAP`（配合 `__getattr__`）兜住按需委派。

> ⚠️ 上游后来把这一层拆成了 `gui_bindings.py` / `gui_proxy.py` / `gui_sinks.py` /
> `gui_engine_context.py` / `gui_proxy_hint.py`；**本仓库尚未跟那次拆分**，所以
> 代理、音量匹配、手腕屏/桌面字幕的生命周期这些方法目前都还在 `vlt/gui.py` 里。
> 搬代码时别照上游的**文件名**找。

三条约定，搬家/拆分时最容易破：

1. **跨模块状态要显式同步**：`gui.py` 与各 `*_ctx`（`EngineCtx` / `AudioCtx` / `DesktopCtx` /
   `ChatCtx`）之间靠 `_sync_engine_ctx()` / `_unsync_engine_ctx()` / `_sync_audio_ctx()` /
   `_wire_desktop_ctx()` + `_E2G` / `_G2E` 两张字段表来回填 —— 新加字段只在一边初始化
   （或不进表）就会出现「界面改了、引擎没看到」。
2. **字体常量**：`ui_tk.apply_ui_font()` 会重绑 `FONT_UI` 等；用
   `from .ui_tk import FONT_UI` 拿到的是 **import 期的占位字族**（Windows 上恰好解析成同一族，
   Linux 上静默回落 → 只有 Linux 路红）。改主题时要确认各 `gui_*` 模块的 `FONT_*` 全局跟着重绑。
3. **可打桩性**：用例会打桩 `vlt.gui.DEFAULT_CONFIG` / `vlt.gui.LevelProbe` 这类**模块级**名字，
   所以实现里要按「定义它的那个模块」取（别图省事在函数里再 import 一份）。

`tests/test_wiring_signatures.py` 用 AST 扫「同模块调用点 vs 函数签名」，专门堵「搬家时只搬了
docstring 没搬形参」这类**单测与 compileall 都抓不住**的事故。

## 六、平台隔离与构建口径

- **构建期禁列清单有两份**（`scripts/build_exe.py` 的 `EXCLUDE_WIN` 喂 `--exclude-module`，
  `scripts/build_appimage.sh` 里另有 `EXCLUDES` 与 heredoc 内嵌的 `forbidden` 参与模块对账），
  加平台独占模块时必须**都改**，另加 `scripts/check_platform_purity.py` 的 `FORBIDDEN` 与
  [平台约束记录.md](../平台约束记录.md) 的清单 —— 只改一份 → 本机绿、CI 的另一条腿红。
- **打包门禁**：磁盘上每个 `vlt/**.py` 都必须进产物；「只定义不调用」的模块会被 PyInstaller 剪掉，
  靠在包 `__init__.py` 里**静态 import 一次**保住。Windows 侧还有
  `scripts/build_exe.py` 的 `missing_vlt_modules()` 对账（`tests/test_build_exe_modules.py` 用纯函数钉住）。
- **产物体积 / 版本对账**：`release.yml` 先对账 tag 与 `vlt/__init__.py` 的 `__version__`，不一致直接红。

各条平台约束的推导与实测数字在 [docs/平台约束记录.md](../平台约束记录.md)，不在本文复述。

## 七、关键不变量（改动前先看这几条）

1. 两条采集路**共用一个泵**，重采样只有一个入口 `to_16k_mono()`；动它必须跑
   [tests/test_resample.py](../../tests/test_resample.py)（判据是拿原始信号当参照算相关性，不是「跑通」）。
2. 输入门限只挂在**环回路**腿；两条 loopback 采集腿共用 `_send_gated()` 这一处口径。
3. 用户可见的失败/降级路径必须留痕（状态栏 + `[...]` 日志各一行），禁静默降级。
4. 界面落盘的参数要**同步回内存中的 `_cfg`**（否则「关掉再勾上」会用旧值重建窗口）；
   往 `output.audio...` 这类**可能整段缺失**的段落写设置，一律走补建父键的写法
   （`config_io._yaml_set_or_create`）。
5. `__version__` 严格 `X.Y.Z`；展示版本另行计算（见 [vlt/version.py](../../vlt/version.py)）。
6. 会话收尾按协议走 `session.finish → finished → close`，别直接掐断连接。
7. **译音 PCM 只有一个出口**：`Engine._emit_translated()`。音量匹配（`vlt/output/level_match.py`）的
   增益必须施加在 `push()` **之前**（字节数不变，下游抖动缓冲靠它算时长）——
   本仓库有四条译音出声路（A 模式 `_on_audio`、B 模式 `_drain_slot_to_mic`、打字流式与非流式），
   新加一条时必须走这个出口，否则那一路不受音量匹配、也不走「译音档没开」的提示。
8. 新增界面文案 = 同步四份词表；新增模块 = 顺手看一眼 `HIDDEN` 与
   [模块索引.md](模块索引.md)（派生表可重跑 `out/devdocs_index_gen.py` 核对）。
