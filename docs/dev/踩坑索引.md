# 踩坑索引（按症状查）

> **怎么用**：手上有一个现象（用户报的 / 日志里的）→ 先在下面第一节按症状找**落点**，
> 到落点读结论，再决定改什么。**别凭直觉改** —— 这张表里几乎每一行都对应一次「凭直觉改错了方向」。
>
> 落点分三类：**代码注释 / 模块 docstring**（最权威，就在现场）、**测试守卫**（判据的可执行形态）、
> **文档**（[平台约束记录.md](../平台约束记录.md) 与仓库 wiki）。
> 仓库 wiki 的引用口径见 [索引.md](索引.md)；它**会被重新生成**，冲突时以代码与测试为准。
>
> 本表已按本仓库删掉了指不到上游专有模块（`gui_sinks` / `test_wrist_*` / …）的行 ——
> 那些功能在本仓库还没同步进来（见 [索引.md](索引.md) 的「与上游的差异」）。

## 二、仓库级约定（代码里**没有**断言的部分）

> 这些是实测得出的口径，落在任何脚本/注释里，所以只能靠人记住；改了行为要同步改这一节。

1. **测试注入的假 API key 会顶掉真凭据**。密钥解析顺序是 *配置 → 凭据存储 → 环境变量*，
   而用例里会 `os.environ.setdefault("DASHSCOPE_API_KEY", "sk-…testonly…")` —— 于是之后任何
   `--self-test` / 复核都会拿假 key 去连服务（`HTTP 401`），看起来像**产物坏了**。
   判定：看日志里 `API 密钥：sk-…****xxxx（N 字符）`，真 key 约 116 字符、测试假 key 是 33/39 字符。
   处置：跑复核前 `unset DASHSCOPE_API_KEY`。⚠️ **置空不等于移除**（`setdefault` 只在键**不存在**时生效）。
2. **全量测试一次只跑一份**：各用例共用 `out/` 沙箱与仓库根的 `config.yaml`，并发跑或被中途 kill
   会互相踩出假红。被 kill 的 run 还可能把 `update_ignored: [9.9.9]` 留在 `config.yaml` 里 →
   之后更新弹窗那条用例永远红（表现为「有更新却没弹窗」）。判据：单独重跑全绿 = 假红，清掉残留行再跑。
3. **复核脚本与端到端脚本不要并行**：端到端脚本开头会清场（杀同名进程），正好会杀掉复核里正在跑的
   `--self-test` → 输出为空、退出码离谱。顺序：先端到端，再单独复核。
4. **`is_newer()` 返回 False ≠ 「不比当前新」**：对**任一边不可解析**的版本号它一律返回 False
   （防御性写法）。所以「没法比」要保守保留并留痕，「真能比且确实不新」才清理；
   预发布版本号（带后缀）既不收更新提示、也发不出更新提示。
5. **文档链接检查只在 CI 的 Linux 腿跑**；本地先跑一次 `scripts/check_doc_links.py` 省一轮往返。
   加锚点（`xxx.md#小节`）前先在目标文件里确认 slug 拼得出来。
6. **源码运行时 `APP_DIR` = 仓库根**（不是 `%APPDATA%`）：探针、真窗口脚本读写的是**仓库根的
   `config.yaml`**（gitignore 里的那份）。所以探针一律把配置指向 `out/` 沙箱，跑完 `git status` 应当为空；
   真窗口探针要用**仓库 venv**（裸 `python` 缺 `pythonosc`，import 阶段就炸，而炸之前配置可能已被改坏）。
7. `scripts/verify/run_suite.sh` 把 worktree 路径当**参数**传给原生 `python.exe`：
   在关掉 MSYS 路径转换的 shell 里（如 Hermes 自己的 shell）要传 Windows 形态
   （`bash scripts/verify/run_suite.sh D:/workspace/tmp/vlt-prN tag`），否则一个用例都不跑。
8. **本机门禁有两个具名放过**：`tests/test_device_wasapi_filter.py`（本机 Voicemeeter 环境红）、
   `tests/test_tts_reuse.py`（时序敏感，本机偶发；单独跑 5/5 过、CI 恒绿）。
   除这两个之外**任何**失败都要当成真红——别把「重跑一次就过了」当结论（见 [验收与门禁.md](验收与门禁.md) §二）。
9. **本仓库是增强线（Extra），不是上游的镜像**：现象先怀疑「这是我们自己加的东西」
   （A/B 音源、通联开关音、音色设计页、延迟埋点、本机调过的常量），
   再看是不是上游同步引入的 —— 差异清单见 [索引.md](索引.md) 的「与上游的差异」。
