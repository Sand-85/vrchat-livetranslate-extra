### 引用口径（`.qoder/repowiki/` 是**只读参考源**）

- 它由 qoder 生成，**会被重新生成**，因此：**不要编辑它，也不要把结论寄存在它里面**。
  需要落成结论的东西写进代码注释 / 本目录 / [平台约束记录.md](../平台约束记录.md)。
- 它**覆盖广但会滞后**（含早期模块划分，如 `vlt/gui.py` 未拆分时的描述）。与代码冲突时
  **一律以代码头部 docstring 与 `tests/` 的断言为准**。
- 引用时给**路径**，不要抄正文 —— 抄下来就会各自过期。
- wiki 内同一主题常有重复条目（`knowledge/zh/` 与 `content/` 两套体系），优先引 `content/`。

## 三、硬规矩（改这个仓库前先认下）

1. **同一件事只有一个家**：口径写一处，其它地方只给链接。仓库已按这条走 ——
   例如 [CONTRIBUTING.md](../../CONTRIBUTING.md) 明确「本文件**不复述**安装步骤」。
2. **文档改动也要过门禁**：新增/改名/改小节标题后跑
   `.venv/Scripts/python.exe scripts/check_doc_links.py`（相对链接按**当前文件所在目录**解析，
   只查 `git ls-files` 里已跟踪的 `.md` —— 新文件要先 `git add` 才会被查到）。
   这一门**只在 CI 的 Linux 腿跑**，别只看 Windows 腿绿了就以为过。
3. **测试必须离线、且一次只跑一份**：全量口径统一用
   `.venv/Scripts/python.exe scripts/run_tests.py`（CI 同款），别自己写 for 循环抄一份。
   全部用例要求离线可跑，「真 API key」类用例（`tests/test_engine.py`）CI 显式跳过。
   本机另有两个**具名**放过（见 [验收与门禁.md](验收与门禁.md) §二）。
4. **平台隔离**：共享代码只走 [vlt/platform/\_\_init\_\_.py](../../vlt/platform/__init__.py) 门面，
   不许 import 平台专有库；Windows 独占模块不许进 AppImage、Linux 独占模块不许进 exe
   （双重清单，见 [平台约束记录.md](../平台约束记录.md) 与 [架构总览.md](架构总览.md) §六）。
5. **用户可见的失败/降级路径必须留痕**（状态栏 + `[...]` 日志各一行），禁静默降级；
   `[xxx]` 那族日志是 `print(..., flush=True)` 进 stdout 的**不是** `logging`
   （`logging.info` 在默认级别下会整条消失）。
6. **`vlt/__init__.py` 的 `__version__` 必须是严格 `X.Y.Z`**：它同时是更新链路正则、
   release tag 对账依据、产物复核断言的目标。带后缀的展示版本另有算法，见
   [vlt/version.py](../../vlt/version.py) 的模块 docstring（本仓库兜底串是 `+Extra`）。
7. **新增任何 `t("…")` 文案，必须同步 `vlt/locales/{en,ja,ko,ru}.py` 四份词表** ——
   key 是中文原文，漏一条 `tests/test_i18n.py` 就红（且界面上会静默回落中文）。
8. **推送到 GitHub 走 REST 脚本**（本机直连 github.com 不可靠）；提交信息里的「验证」段
   要写**实际跑过什么、结果如何**，别把「打算跑」写成「已验证」。

## 五、与上游的差异（本仓库 = Extra 线）

本仓库是上游的**增强分支**（`Sand-85/vrchat-livetranslate-extra`），从上游早期分叉出来，
**不是**逐提交跟随。同步上游时按下面的口径判：

**① 有意与上游不同（同步时绝不要改回去）**

| 项 | 上游 | 本仓库 |
|---|---|---|
| 展示版本兑底串 | `0.11.0+unknown` | **`0.11.0+Extra`**（一眼认出增强线） |
| 版本号线 | 跟上游 | 自 v0.8.2 起**脱钩**（加功能 +minor、只修 bug +patch） |
| 发布产物 | Windows + AppImage | **只发 Windows**（exe + `SHA256SUMS.txt`）；CI 里 AppImage 腿保留 |
| 发版说明 | GitHub 自动生成 | **手写在** `.github/workflows/release.yml` 的 `body: |` |
| 参考文档 | 五语 GUIDE 全 | 保留用户手改的部分（`docs/GUIDE*.md` / `README.md`） |
| Linux 实现 | 全收 | **上游新增的 Linux 实现不拉**；仓库里既有的 Linux 代码与 AppImage CI 保留 |
| GUI 结构 | 薄壳 + `gui_bindings` / `gui_proxy` / `gui_sinks` / `gui_engine_context` / `gui_proxy_hint` | **尚未做那次拆分**：`_DELEGATE_MAP` 与代理/引擎相关方法目前都在 `vlt/gui.py` 里 |

**② 本仓库独有的功能**（上游没有 → 出问题先想到「这是我们自己的」）

- **A/B 译音音源热切换**（`output.audio.mode`: `realtime` / `tts`）与 B 模式的分段合成流水线
  （`vlt/engine.py` 的 `_drain_slot_to_mic` / `_voice_mode` / `segment_tts`）—— 音色与打字腿一致；
- **通联开关音**（[vlt/sfx.py](../../vlt/sfx.py)，句首/句尾的「哔」；可绑音色、独立增益）；
- **音色设计与复刻页**（[vlt/voice_lab.py](../../vlt/voice_lab.py) + [vlt/gui_voicelab.py](../../vlt/gui_voicelab.py)，
  走 Qwen-Audio-TTS 专用通道）；
- **延迟埋点**（[vlt/latency.py](../../vlt/latency.py)，`VLT_LATENCY_TRACE=1` 打开）；
- **平台侧按本机实测调过的常量**（音频缓冲、SFX 默认增益等），改前先看代码注释里的实测数字。

**③ 同步上游时的既有手法**（反复用过，别再发明）

- 分批搬、**绝不整树合并**；每批只碰几个文件、解完就跑门禁与推送；
- **不许整文件取上游**的文件：`vlt/engine.py`（我们与上游大幅分叉）、`vlt/gui.py`（结构性差异）、
  `vlt/platform/win.py`（上游删了我们的线程提速）；判据是「`git diff HEAD upbase -- <file>` 有差异」；
- 与上游同步**没有**自动化的 merge 基线：`main` 的历史是 REST 重建过的，祖先判定不可靠。
