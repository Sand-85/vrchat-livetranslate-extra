## 0. 最速で始める：用意された exe をダウンロード

**[Releases](https://github.com/nixi-agent/vrchat-livetranslate/releases/latest)** から
**`VRChatLiveTranslate.exe`** を入手し（**単一ファイル・インストール不要・コンソールウィンドウなし**）、
ダブルクリックするだけです。

- **Qwen Cloud の API key** はご自身で用意してください。「⚙ 設定」で貼り付けて保存します
- 設定とログは `%APPDATA%\vrchat-livetranslate` に置かれます（読み取り専用フォルダに exe を置いても動作します）
- ポータブル運用（設定を exe と同じ場所に）したい場合は、exe の隣に**空の `portable.txt`** を置きます
- 古いバージョンが exe の隣に `config.yaml` / `logs/` を残している場合、初回起動時に**自動で新しい場所へ移行**します。元のファイルは削除されません

### 自動更新されますか？

**自動で確認はしますが、勝手にインストールはしません** — 更新するかどうか、いつするかは常にあなた次第です：

- 起動のたびにバックグラウンドで一度だけ静かに確認します。確認に失敗しても（ネットワーク不通など）邪魔はせず、ログに残すだけです
- 新しいバージョンが見つかると、3 つの選択肢があるダイアログが出ます：
  - **今すぐ更新** → 自動でダウンロードします（1〜2 分程度）。完了後に「今すぐ再起動して更新」を押せばその場で切り替わり、
    「後で更新」を押せばアプリを閉じるときに差し替えられ、次回起動から新バージョンになります
  - **次回にする** → この起動中はもう表示しません。次回の起動時にまた確認します
  - **このバージョンは通知しない** → そのバージョンだけ無視します。次のバージョンでは改めて通知します
- ダウンロード失敗時は再試行できます。ウィンドウ内の「ダウンロードページを開く」から Releases に取りに行くこともできます
- ポップアップが出ていないときに確認したい → 「⚙ 設定 → ソフトウェア更新 → 更新を確認」
- 更新で**設定と API key が失われることはありません**。更新後は次回起動時にお知らせします

**ソースから実行している場合**：上記は適用されません。リポジトリで `git pull` してください
（ソース実行時に「今すぐ更新」を押しても同じ案内が出ます）。

ソースを読みたい／自分でビルドしたい／改造したい → 下の「1.」からどうぞ。

## 1. 前提条件

1. **Windows 10 / 11**（WASAPI と SteamVR を使用します）
2. **Python 3.11**（3.12 は未検証。インストール時に *Add python.exe to PATH* にチェック）— *exe を使うだけなら不要*
   <https://www.python.org/downloads/release/python-3119/>
3. **VRChat**：設定で OSC を有効化（`OSC enabled: True`）し、チャット吹き出しの表示を **Everyone** にします
4. **SteamVR** — 「相手の発話 → 手首オーバーレイ」を使う場合のみ必要
5. **Qwen Cloud の API key**（個人の実名認証で OK）

## 2. インストール（ソースから）

**`setup.bat`** をダブルクリックします（`.venv` の作成と依存関係の導入、1〜2 分程度）。

手動で行う場合：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 3. API key の設定

> 🔑 Qwen Cloud のアカウントをお持ちでない場合はこちら → **[Qwen Cloud に登録 ▸](https://www.qianwenai.com/)**

以下の順に探索し、**最初に見つかったものが使われます**：

| 優先度 | 取得元 | 設定方法 |
|---|---|---|
| 1 | GUI で保存した key | 「⚙ 設定 → API key」で貼り付けて保存（`%USERPROFILE%\.vrchat-livetranslate\api_key.txt` に保存） |
| 2 | 環境変数 | `setx DASHSCOPE_API_KEY "sk-your-key"`（**新しく開いたターミナルでのみ有効**） |
| 3 | Bailian CLI の設定 | `bl auth login --api-key "sk-your-key"`（`npm install -g bailian-cli` が必要）／`%USERPROFILE%\.bailian\config.json` を読みます |

**key を読むのはこの 3 か所だけで、プロジェクト内のファイルや `config.yaml` には書き込みません。**

> 🔒 **コミット時の安全装置**：リポジトリには認証情報スキャンが同梱されています。`install_secret_guard.bat` を
> 一度実行して pre-commit フックを入れておくと、`sk-...` / `gho_...` / `AKIA...` / `Bearer ...` などの
> ハードコードされた秘密情報を含むコミットはその場で拒否されます（スクリプト：`scripts/check_no_secrets.py`）。
> 手動での全走査：`python scripts/check_no_secrets.py --once`
> 理由：key が一度 git の履歴に入ると、ファイルを消しても残ります。履歴の書き換えが必要になる前に止めるべきです。

## 4. セルフチェック

**exe を使う場合**：起動して次の 3 点を確認してください。

1. 「⚙ 設定」で 3 つのデバイスドロップダウンが空でないこと（`マイク` / `VRChat の音声` / `翻訳音声の出力`）
2. API key の状態が**設定済み**になっていること（未設定の場合はクリックすると登録ページが開きます）
3. `chatbox` にチェックを入れ、「翻訳を開始」を押してマイクに一言話す → 吹き出しに訳文が出ること

**ソースから実行する場合**：**`run_selfcheck.bat`** をダブルクリックします。次の 4 つを順に実行し、最初の 3 つはマイクも VRChat も不要です。

1. モジュールのインポート確認（engine / session / overlay / chatbox / merger）
2. API key を一度読み、マスクして表示（優先順位の確認）
3. 手首オーバーレイの 1 フレームをオフライン描画（SteamVR を占有しません）
4. 同梱のテスト音声をパイプライン全体に通す（中国語 → 英語、chatbox へ）

VRChat が起動していれば、吹き出しに次のように表示されるはずです：

```
Hello, I'm Nixi. Today, we're going to test out the real-time simultaneous interpretation feature in VRChat.
```

**不具合を報告する前に、必ずこのセルフチェックを実行してください。**

## 5. 使い方

### GUI（推奨）

**exe をダブルクリック**、またはソース版なら **`run_gui.bat`** をダブルクリックします（どちらも同じウィンドウです）。
（Tkinter のみ使用・標準ライブラリだけで動作・追加依存ゼロ・即起動）

| エリア | 内容 |
|---|---|
| 1 行目 | `翻訳を開始` / `翻訳を停止`、方向のラジオボタン（`自分` / `相手` / `双方向`）、言語ペアのドロップダウン（原文 → 訳文）、右側に `☕ サポート` と `⚙ 設定` |
| 2 行目 | `出力:` の `chatbox` / `手首オーバーレイ` / `翻訳音声を出力` チェックボックスと `微調整 ▸` ボタン。右端に API key の状態（設定済みなら `API key 設定済み`、**未設定ならクリックできる「⚠ API key 未設定 ・ Qwen Cloud の登録はこちら ▸」**） |
| チャット欄 | 右の青い吹き出し＝自分の発話、左の灰色＝相手の発話。1 つの吹き出しは 2 行構成で、**上に原文を小さく、下に訳文を大きく**表示。履歴はスクロール可（最大 500 件） |
| ステータスバー | 左：色付きの丸印＋最新の状態メッセージ／右：統計（`実行中` / `{n} 件翻訳` / `初回差分 {ms}ms`）。両者は重なりません |
| 下部バー | **テキスト入力**：`テキスト入力:` 欄と `送信`。**Enter で送信**（`Esc` でクリア）。方向に「自分」が含まれるときだけ有効で、それ以外はグレーアウトします |
| `☕ サポート` ポップアップ | Ko-fi のリンクボタンと WeChat / Alipay の QR コード（240 px に比例縮小。そのまま読み取れます） |

- **ストリーミング表示**：未確定の差分は新しい吹き出しを追加せず、**同じ吹き出しをその場で書き換え**ます
- **双方向**：1 つのウィンドウで 2 方向を翻訳します（マイク → 右側、ゲーム音声 → 左側）。2 本目は**300 ms ずらして開始**し、オーディオデバイスの取り合いを避けます。片方が失敗しても、もう片方は動き続けます
- **言語のミラーリング**：1 つのペアで両方向をカバーします。「中国語 → 英語」を選べば、相手の発話方向は自動的に「英語 → 中国語」になります。
  原文側は `自動検出` / 中国語 / 英語 / 日本語 / 韓国語 / フランス語 / ドイツ語 / スペイン語 / ロシア語から選べます（訳文側は同じ表から「自動検出」を除いたもの）。
  原文側で `自動検出` を選ぶと、相手方向の訳文は中国語にフォールバックし、その旨がステータスバーに出ます。変更は**即時反映**され、設定に書き戻されて次回起動時も保持されます
- **設定ダイアログ**（`⚙ 設定`）：API key の登録／削除、3 つのオーディオデバイスドロップダウンと `再スキャン`、ログ欄（`ログを ZIP でエクスポート…`）
- **微調整パネル**（`微調整 ▸`）：手首オーバーレイのアンカーと 12 個のスライダー。**ドラッグで即時反映、再起動不要**（「6. 設定」参照）
- **テキスト入力**：話したくないときにキーボードで代用します。下部バーに入力して **Enter で送信**。訳文は音声経路と**まったく同じ**下流（チャット吹き出し／手首オーバーレイ／chatbox）を通ります。「翻訳音声を出力」をオンにすると**読み上げも行い**、訳文を TTS で合成して仮想サウンドカードへ書き込むので相手にも聞こえます（「6. 設定」の `text_input.tts` 参照）。これは**マイクの代替**なので、方向に「自分」が含まれるときだけ使えます（含まれないときは入力欄がグレーアウトします）

#### 自動検証（ヘッドレス・ウィンドウを開かない）

```bat
:: ソース版
.venv\Scripts\python.exe -m vlt.gui --self-test
.venv\Scripts\python.exe -m vlt.gui --self-test-dual

:: exe（コンソールウィンドウなし。結果はログに出ます — ビルドスクリプトの自己検証と同じ方法）
VRChatLiveTranslate.exe --self-test
```

成功すると `GUI_SELFTEST_OK` / `GUI_SELFTEST_DUAL_OK mine=N theirs=N` を出力し、失敗すると `..._FAIL: ...` を stderr に出して非 0 で終了します。実際の API key が必要です。

> 🪵 **クラッシュログ**：GUI は起動のたびに `logs/` 配下に `gui_<タイムスタンプ>.log` を書き出します。
> 中には**バージョン情報**（git HEAD）、Python 環境、stdout/stderr のすべて（各行に `HH:MM:SS.mmm` の
> タイムスタンプ付き）が入ります。ネイティブクラッシュ（`faulthandler`）、メインスレッドの例外、
> 子スレッドの例外、Tk コールバックの例外の 4 種類を捕捉します。クラッシュ時は**このファイルを
> メンテナーに送れば原因を特定できます** — ウィンドウが閉じると何も残りません。
> 1 ファイル 2 MB でローテーションし、合計 5 MB を超えると古いものから削除されます。「設定」から
> まとめて**秘匿処理済み**の ZIP としてエクスポートできます。

### コマンドライン（ソース版のみ）

exe はコンソールのない単一ファイル GUI なので、上記の `--self-test` 以外にコマンドライン用途はありません。CLI はソース版でのみ意味があります。

```bat
:: 自分の発話 → chatbox（実際に VRChat へ送信）
.venv\Scripts\python.exe -m vlt.app --direction mine --mic --sink chatbox

:: 相手の発話 → 手首オーバーレイ（SteamVR の起動が必要）
.venv\Scripts\python.exe -m vlt.app --direction theirs --loopback --sink overlay

:: VRChat なしで経路を検証：同梱のテスト音声を通す
.venv\Scripts\python.exe -m vlt.app --direction mine --pcm testdata\zh_test_16k.pcm --dry-run
```

両方向を同時に翻訳する → **コマンドラインウィンドウを 2 つ開きます**（または GUI の「双方向」を使えば 1 つのウィンドウで 2 セッション動きます）。
方向ごとに独立した WebSocket セッションを持つため干渉しません（レート制限は RPM 10 で十分余裕があります）。

コマンドが長くて面倒なら、用意された bat を使ってください：**`run_chatbox.bat`**（自分の発話 → 吹き出し。先にデバイス一覧を出してから開始）と
**`run_overlay.bat`**（相手の発話 → 手首オーバーレイ）。

#### すべてのパラメータ

| パラメータ | 効果 |
|---|---|
| `--direction mine/theirs` | `config.yaml` のどちらの方向を使うか |
| `--mic` / `--loopback` / `--pcm <file>` | 音声ソース：マイク／VRChat の再生出力／オフライン PCM（いずれか 1 つ。優先度は `--pcm` > `--mic` > `--loopback`） |
| `--sink chatbox/overlay/both` | 出力先（既定は `chatbox`） |
| `--list-devices` | オーディオの入出力デバイスを一覧表示して終了 |
| `--dry-run` | 実際には OSC を送らず、表示とパケットのダンプのみ |
| `--overlay-dry-run` | オーバーレイが SteamVR を占有せず、各フレームを `out/overlay_frames/` に PNG 出力 |
| `--audio-out` | 翻訳音声の出力を有効化（`config.yaml` の `output.audio.enabled` を上書き） |
| `--audio-device <name...>` | 仮想サウンドカード名のフォールバック順（`config.yaml` の既定を上書き） |
| `--no-realtime` | PCM を可能な限り高速に流す（リアルタイム制限なし。`--pcm` と併用時のみ意味があります） |
| `--settle-s <seconds>` | 音声終了後、応答を待つ秒数（既定 8） |
| `--config <path>` | 別の設定ファイルを使う |

> マイク入力は**連続で動き続けます**：`Ctrl+C` まで止まりません（時間指定のパラメータはありません）。
>
> 📌 **オーディオデバイスの指定にフラグは不要**：GUI の「⚙ 設定」で選ぶか（ドロップダウンの先頭「自動検出」が
> フォールバック順に探索します）、`config.yaml` の `capture.mic_device` / `capture.loopback_device` を直接編集します。
> 保存されるのは**デバイス名の文字列**で、インデックスではありません — インデックスは抜き差しやセッション切り替えで丸ごとずれます。

## 6. 設定（`config.yaml`）

> 📄 **初回起動時に `config.example.yaml` から `config.yaml` が自動生成されます。**
> `config.yaml` は**あなた自身の設定**（デバイスの選択、言語の好みなど）で、gitignore されており
> **バージョン管理には入りません**。デバイス名などはマシンごとに異なり、混ざるだけだからです。
> 既定に戻したいときは削除して再起動してください。
>
> 置かれる場所：
> - **exe**：`%APPDATA%\vrchat-livetranslate\config.yaml`（`portable.txt` があるポータブル構成では exe の隣）
> - **ソース版**：リポジトリ直下の `config.yaml`
>
> 🛟 **設定が壊れても起動できなくなりません**：YAML の解析に失敗した場合、そのファイルは自動で
> `config.yaml.broken` として退避され、テンプレートから新しい設定が生成され、理由が表示されたうえで起動が続きます。

GUI で変更したもの（方向、出力チェック、言語、デバイス、手首オーバーレイの微調整）は、このファイルに**その場で書き戻されます** —
変わるのはその 1 行だけで、**コメント・空行・キーの順序はすべて保持されます**（生成された YAML は書き込み前に検証され、不正な出力は拒否されます）。

### 主要なキー

```yaml
session:
  model: qwen3.8-livetranslate-flash-realtime   # qwen3.5-* も可（イベント名は世代ごとに自動で振り分け）
  base_url: wss://dashscope.aliyuncs.com/api-ws/v1/realtime
  voice: Tina                 # ⚠️ 必ず明示。未設定だと Voice 'Chelsie' is not supported で失敗
  turn_detection: null        # 空 = サーバー既定
  final_silence_s: 3.0        # ⚠️ サーバーの増分間隔（実測最大 2.3s）より大きくすること。小さくすると文の途中で確定版が飛びます
  max_new_sessions_per_minute: 4   # RPM 10 の予算：WS 接続 1 回でリクエスト 1 回と数えます
  reconnect_backoff: [2, 5, 10, 30]

capture:                      # 空文字列 = 自動検出
  mic_device: ""
  loopback_device: ""

directions:
  mine:   { source_lang: zh,   target_lang: en, output_audio: false }   # 自分 → 吹き出し
  theirs: { source_lang: null, target_lang: zh, output_audio: false }   # 相手 → 手首オーバーレイ（null = 自動判定）

chatbox:
  interval_s: 2.0             # 増分の更新間隔（漏れバケツ 5 件/5 秒 → 2 秒に 1 件なら余裕あり）
  max_chars: 144              # 公式上限（バイトではなく文字数）

text_input:                   # テキスト入力（下部の入力欄、Enter で送信）
  enabled: true               # false = 入力行を表示しない
  model: qwen-mt-flash        # タイピング翻訳は**テキスト**モデル。qwen-mt-plus も可
                              # ⚠️ qwen3-livetranslate-flash は不可：実測でテキスト入力に対して原文をそのまま返します
  timeout_s: 20               # 1 回の翻訳のタイムアウト（秒）
  tts:                        # タイピングでも読み上げる（訳文を TTS で合成 → 仮想サウンドカード → 相手に聞こえる）
    enabled: true             # 「翻訳音声を出力」がオンで、方向に「自分」が含まれる必要があります。オフならこの段は自動でスキップされ、テキストのみ
    model: qwen3-tts-flash    # qwen3-tts-instruct-flash も可
    voice: Cherry             # 多言語音色（中／英／日で読み上げ可能なことを実測済み）
    timeout_s: 30

merger:
  interval_s: 2.0             # 最初の差分は即時、以降 2 秒ごとにスナップショット、文末では必ず確定版
  carry_over: false           # true = 直前の確定訳文を接頭辞として残す（連続字幕の見え方）

overlay:
  interval_s: 0               # 0 = 更新があれば即座に表示（ローカル表示は chatbox のレート制限を受けません）
  anchor: right_hand          # left_hand | right_hand | tracker | hmd
  size_px: [1024, 320]
  font_size: 42               # 訳文の文字サイズ
  source_font_size: 30        # 原文の文字サイズ
  show_source: true           # 2 行表示（3.8 は既定で原文の認識結果も返すため追加コストなし）

output:
  audio:
    enabled: false            # 翻訳音声の総スイッチ：directions.<X>.output_audio との AND
    device_name: ""           # 手動指定の仮想サウンドカード名（空でなければフォールバック順より優先）
```

### 手首オーバーレイの微調整パネル（12 個のスライダー、ドラッグで即反映）

| スライダー | 範囲 / 刻み | スライダー | 範囲 / 刻み |
|---|---|---|---|
| 位置 X / Y / Z | −0.30 ~ 0.30 m、0.005 | サイズ | 0.05 ~ 0.80 m、0.01 |
| ピッチ / ヨー / ロール | −90 ~ 90°、1 | カーブ | 0.0 ~ 0.50、0.01 |
| 不透明度 | 0.10 ~ 1.00、0.05 | 訳文の文字サイズ | 20 ~ 64、1 |
| 原文の文字サイズ | 14 ~ 48、1 | パネルの高さ | 240 ~ 560 px、10 |

ほかに **アンカー**のドロップダウン（右手 / 左手 / 前腕トラッカー / HMD 前方固定）と **トラッカー番号**（0〜3）があります。
変更は 200 ms のデバウンスでディスクに書き込まれ、**訳文の文字サイズ / 原文の文字サイズ / パネルの高さ**は
テクスチャを 1 フレーム再描画し、それ以外は変換行列の再適用のみです。

> 実測の目安：文字サイズ 42/30 + パネル 320 px で**会話 2 ラウンド**、36/24 + 420 px で**3 ラウンド・6 行**。

## 7. トラブルシューティング

| 症状 | 原因 / 対処 |
|---|---|
| 吹き出しに何も出ない | VRChat が起動していない／OSC がオフ／吹き出しの表示が Off。`--dry-run` で送信ログが出るならプログラム側は正常です |
| `[loopback] ❌ no loopback device found` | VRChat が音を再生していない、または**リモートデスクトップ経由で操作している**（WASAPI のエンドポイントはセッションごとに分離されるため、物理マシンの現在のセッションで動かす必要があります） |
| マイクが何も拾わない | 上と同じ。まず「⚙ 設定」のドロップダウンで選ばれているデバイスを確認してください（リモートセッションでは列挙が空になるのが正常である旨、ステータスバーに表示されます） |
| `Voice 'Chelsie' is not supported` | `session.voice` が未設定です。`Tina` のままにしてください |
| `Invalid translation parameter` | `session.update` に `translation` フィールドがありません（コード側では保証済み。改変するときは注意） |
| `1007 Requests rate limit exceeded` | RPM 10 に到達しました。1 分待ってください。頻繁な再起動は避けてください（**WS 接続 1 回ごとにリクエスト 1 回**と数えます） |
| 翻訳が文の途中で止まる | 無音フォールバックのしきい値が下がっています。`session.final_silence_s` は 2.3 s より大きく（既定 3.0） |
| `[overlay] ⚠️ SteamVR not running or unavailable` | 正常な縮退動作です。手首オーバーレイが出ないだけで、chatbox には影響しません |
| 手首オーバーレイが見えない | まず SteamVR が起動しているか確認し、「微調整」で位置／サイズを調整してください。`--overlay-dry-run` で PNG が出るなら描画自体は正常です |
| しばらくすると手首オーバーレイが消える | 2 段階の自己修復が入っています（3 回連続失敗 → オーバーレイを再構築 → さらに 3 回 → openvr 接続をハード再起動 → 以降は 50 回に 1 回だけ再試行）。ログには 30 秒ごとに `[overlay][diag] heartbeat: …` が出て、「最後の成功からの経過時間／再構築回数」を確認できます |
| 翻訳音声が出ない | ① 2 つのスイッチが両方オンか（出力チェックと方向ごとの設定）② 「自分」方向でのみ動作します ③ 仮想サウンドカードは入っていますか。理由はステータスバー／ログに明示されます ④ **それ以外の機能には影響しません** |
| GUI で「翻訳を開始」を押しても何も起きない | まずターミナルの出力を確認してください。asyncio コールバック内の例外は 1 行のトレースバックがコンソールに出るだけで、ステータスバーには出ません（exe の場合は `logs/` の最新 `.log`） |
| 意味の分からないエラー | **「⚙ 設定 → ログを ZIP でエクスポート」** — 自動で秘匿処理されます。ZIP をメンテナーに送ってください |

## 9. 開発

### テストの実行

**pytest は使いません**（依存に入っていません）。各テストファイルは独立した実行可能スクリプトで、CI が動かすものと同一です：

```bat
:: 全部（ファイル単位、CI と同一。cmd に直接貼り付け — .bat ファイル内では %t を %%t に）
for %t in (tests\test_*.py) do @.venv\Scripts\python.exe %t

:: 単体
.venv\Scripts\python.exe tests\test_virtualmic.py
```

テストは**すべてオフラインで動作します**（マイク / VRChat / SteamVR / ネットワーク不要）。デバイスの解決、パスの決定、
再接続、ログのローテーションと秘匿処理、サポートポップアップ、手首オーバーレイの自己修復、
翻訳音声バッファの不変条件、コメントを保つ設定の書き戻しなどをカバーしています。

唯一の例外は `tests/test_engine.py` で、実際のセッションを 1 つ開くため**そのマシンに設定済みの API key が必要**です。
CI では明示的にスキップされます（ワークフローが理由を `::notice::` で出力します — 黙ってスキップはしません）。

### パッケージング

```bat
build_exe.bat                                              :: ビルド + その後の自己チェック
.venv\Scripts\python.exe scripts\build_exe.py --no-verify  :: ビルドのみ
```

出力は `dist\VRChatLiveTranslate.exe`：PyInstaller の**単一ファイル・コンソールウィンドウなし**で、
`config.example.yaml` / `testdata` / `assets` を同梱し、約 37 MB です。
既定ではビルド後に `exe --self-test` を実際に 1 回実行し、ログに `GUI_SELFTEST_OK` が出たときだけ合格とみなします。

### CI / リリース

- **CI**（`.github/workflows/ci.yml`、main への push / PR / 手動）：
  構文チェック → 認証情報スキャン → オフラインテストをファイル単位で全実行 → さらに別途**パッケージング工程**の確認（成果物が存在し 20 MB 以上）
- **リリース**（`.github/workflows/release.yml`、`v*` タグの push で起動）：
  まずタグと `vlt/__init__.py` の `__version__` を突き合わせ（不一致なら即失敗）→ パッケージ →
  **exe** と `SHA256SUMS.txt` を添付した Release を作成（チェックサムは GitHub が添付の横に `sha256:…` として表示します。このファイルは v0.2.0 以前のクライアント向けの移行措置です）
- **ダウンロードしたものを自分で検証したい場合**：`scripts/verify_release.py` が Release の成果物を取得して突き合わせます
  （SHA256、`--self-test` の実実行、バージョン行、新機能の文字列をバイトコードから検索、アイコンのピクセル比較）：

  ```bat
  .venv\Scripts\python.exe scripts\verify_release.py v0.2.2 "手腕屏没启动起来"
  ```

## 10. 既知の制限

- 手首オーバーレイには **SteamVR がアクティブなコンポジタであること**が必要です。ベンダー純正の OpenXR ランタイムでは、サードパーティ製の PC 側オーバーレイは表示されません
- 入力側は**ゲームのミックス音声の 1 ステレオチャンネルしか取得できません**：話者ごとのチャンネルは存在しないため、複数人が同時に話すと話者の特定は原理的に不正確です
- WebSocket 経路には**エコーキャンセルもノイズ抑制もありません** → **ヘッドホンの着用が必須**です（スピーカーだと相手の声も拾ってしまい、同じ文が二重に認識されます）
- 両方向を同時に翻訳する = WebSocket セッション 2 本で、予算も両方に計上されます
- **タイピング + 読み上げは「翻訳 + TTS」の 2 リクエスト**です。テキストはほぼ即座に出ますが、音声は TTS の合成待ちになります（実測でエンドツーエンド約 2.6 秒）。
  そのため吹き出しで見えてから 1〜2 秒遅れて相手に届きます。声は TTS の音色（既定 `Cherry`）で、音声経路のリアルタイムモデルの声とは**同じではありません**。
  条件は 3 つ目の系統と同じで、「翻訳音声を出力」がオンかつ仮想サウンドカードがある場合のみ。それ以外は自動でスキップされ、テキストだけになります
- **タイピングはマイクの代替**です：そのため方向に「自分」が含まれるときだけ使え、かつ「翻訳を開始」を押した後でのみ有効です
- **chatbox に載るのは「自分が話した内容」の訳文だけ**です：相手の発話の訳文は chatbox の吹き出しには入りません。手首オーバーレイか GUI のチャット欄を見てください
